Privacy Policy

Effective date: October 8, 2026

This Privacy Policy explains how LoungeFeed Project operates LoungeFeed and handles information when users connect content sources to watch their own authorized feeds on Apple TV.

Overview

LoungeFeed is a local-first viewing product. The Apple TV app connects to a LoungeFeed Host app running on a user's Mac or iPhone. The Host handles source authorization, local pairing, local cache, and read-only content access for the paired Apple TV viewer.

LoungeFeed is designed for viewing. It does not post, like, follow, comment, send messages, or perform other writing actions on a connected source account. Favorites and collections created in LoungeFeed are local viewing features and do not alter the originating service.

Information we access

Depending on which sources a user connects, LoungeFeed may access the following information through the source's official authorization flow or API:

  • Basic account identity, such as display name, username, and avatar.
  • Read-only feed, board, channel, pin, post, reply, message, image, and video metadata that the user is authorized to view.
  • Media URLs or media identifiers needed to display authorized images and videos inside LoungeFeed.
  • Local pairing status between the Host and the user's Apple TV viewer.

LoungeFeed requests only the access needed to provide the selected read-only viewing features for each connected source.

Information we do not collect

  • LoungeFeed does not collect source passwords. Sign-in takes place through the connected source's authorization experience.
  • LoungeFeed does not collect payment card numbers through this website.
  • LoungeFeed does not sell personal information.
  • LoungeFeed does not use connected accounts to publish or modify source content.

Where data is stored

Source authorization tokens, local cache, media cache, and pairing data are stored on the user's Host device. LoungeFeed does not operate a cloud service that receives or stores users' source tokens or feed contents.

Local Host discovery uses generic product names such as LoungeFeed Mac Host and LoungeFeed iPhone Host. LoungeFeed does not publish the user-configured name of a Mac or iPhone in its local discovery information.

Viewer keeps a bounded diagnostic journal on the Apple TV. While paired, Viewer can automatically relay these diagnostic events to the user's Host over the local network. This local delivery does not upload a report to LoungeFeed's cloud support service.

Only an explicit user action sends a diagnostic report to our cloud support service: selecting Send diagnostic report in Viewer Settings > Support diagnostics, sending a report from Host, or uploading a report through the Support page. Opening the diagnostics screen alone does not send a report. Reports are stored in a private Cloudflare R2 bucket for troubleshooting and are automatically deleted after 30 days.

If a user explicitly selects Report displayed content in LoungeFeed Viewer, LoungeFeed stores a small report in the same private support bucket. It contains a random Support ID, one-way opaque identifiers for the displayed item and (when available) its author, an enumerated report reason, safety labels or scores already available to the Viewer, and the app version. It does not contain post text, images, video, source credentials, cookies, or private source links. These reports are automatically deleted after 30 days.

If a user opens the optional Apple TV content-controls page by scanning a code shown on their television, LoungeFeed stores a random Apple TV identifier, a one-way hash of a device key, the selected preference, and (when enabled) the time of age confirmation in Cloudflare D1. This record does not contain feed content, media, source credentials, account names, or Apple Account information. The short-lived code session expires after 10 minutes. Disabled preference records are automatically removed after 90 days without activity. Explore uses a separate temporary sample session with random identifiers, hashed keys and a sample preference. It expires after 10 minutes, is removed during subsequent service activity, and cannot change normal Apple TV preferences or subscription entitlements.

Optional support diagnostics

A diagnostic report can include:

  • A random Support ID and random diagnostic session identifier, app version and build, platform, event timestamps, and source categories.
  • Product-interaction states for connection, feed loading, playback, content controls, and subscription operations.
  • Performance data such as operation duration, playback startup time, and stall counts or duration.
  • Other diagnostic data such as network and storage state, retry counts, and technical error domains and codes.
  • Purchase-history information limited to Viewer subscription tier, Monthly or Yearly period, current entitlement, and pending renewal-plan state.

Before upload, reports use a restricted set of diagnostic fields. They exclude Apple Account identity, passwords, receipts, transaction IDs, source account names, credentials, cookies, request bodies, private source URLs, feed text, and media. Diagnostic session identifiers are random and are not joined to the content-controls installation identifier, an Apple Account, or a source account. We use reports to diagnose and resolve app-functionality problems, not for advertising, tracking, or profiling.

Subscriptions and purchase information

Apple handles subscription billing. LoungeFeed Viewer uses StoreKit on the device to determine the currently active plan, subscription period, and pending renewal plan. LoungeFeed does not receive payment card numbers. An optional support diagnostic report may include the limited subscription-state information described above, but never an Apple Account identity, receipt, or transaction ID.

How we use information

LoungeFeed uses authorized information to:

  • Show the user's selected feeds and media on Apple TV.
  • Display account connection status in the Host app.
  • Cache content locally for performance and playback reliability.
  • Protect users from unsafe or unwanted content where content safety controls apply.
  • Diagnose and resolve Viewer or Host connectivity, playback, content-control, and subscription problems when a user sends a support report.

Source-specific access

Source capabilities vary according to the access each service makes available. LoungeFeed's Pinterest integration uses Pinterest OAuth and authorized API access in read-only mode to display the user's authorized account identity, boards, and pins. It does not create, edit, delete, or save pins; follow accounts or boards; post comments or messages; access Pinterest passwords or session cookies; or scrape Pinterest web pages.

Third-party content and safety

LoungeFeed displays user-generated content supplied by the connected services. LoungeFeed does not host that content or let users publish content through LoungeFeed. Posts identified by a connected service or LoungeFeed's on-device safety checks are filtered by default.

In LoungeFeed Viewer, a user can hide a displayed post or mute its author locally. These choices are stored only on that Apple TV and can be restored in Settings. A user can also send the privacy-safe displayed-content report described above. When a safe public post link is available, LoungeFeed can show a QR code that opens the originating service so the user can use that service's own reporting, muting, blocking, and removal tools. Concerns can also be sent to loungefeed@outlook.com. Do not include passwords, access tokens, cookies, or private account information.

Sharing

LoungeFeed does not sell source data or feed contents. Content is shared locally from the Host to the paired Apple TV viewer so the user can watch it. LoungeFeed uses Cloudflare to store the optional support reports and content-control preferences described above, and platform services such as Apple, GitHub Pages, or domain/DNS providers to operate the app, website, or distribution infrastructure. These services are not used to sell source account data.

User choices

  • Users can disconnect a source account inside LoungeFeed Host.
  • Users can clear local cached media and local feed data inside LoungeFeed Host where cache controls are available.
  • Users can revoke source authorization through the connected source's own account settings.
  • Users can use Viewer and Host without sending cloud support diagnostic reports. To request earlier deletion of an uploaded report, contact Support with its Support ID; do not include passwords, receipts, or private feed content.
  • Users can uninstall LoungeFeed Host to remove local app data according to the operating system's app data behavior.

Children

LoungeFeed is not directed to children under 13. Users should only connect accounts they are authorized to use and view.

Changes

We may update this Privacy Policy as LoungeFeed changes. The effective date at the top of this page will be updated when material changes are made.
